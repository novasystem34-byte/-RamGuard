# RAM Guard
[![Donate](https://img.shields.io/badge/Donate-PayPal-00457C?logo=paypal)](https://paypal.me/Alaaabushamaa)

تطبيق WPF (.NET 8) لمراقبة وضبط استهلاك الذاكرة للعمليات الشغالة بويندوز.

## طريقة البناء والتشغيل

يحتاج **Windows** (ما يشتغل على لينكس/ماك) + **.NET 8 SDK**.

```bash
dotnet restore
dotnet build -c Release
dotnet run
```

أو افتح `RamGuard.csproj` مباشرة بـ Visual Studio 2022 (بس اختار Workload
".NET Desktop Development").

> التطبيق يطلب صلاحيات **Administrator** تلقائيًا عند التشغيل (موجودة
> بملف `app.manifest`). بدون هالصلاحيات أغلب عمليات النظام ما راح
> تقدر تقرأ مساراتها أو تطبّق عليها حدود ذاكرة.

## شو يسوي فعليًا

| الميزة | الآلية | مستوى الأمان |
|---|---|---|
| عرض كل العمليات + الرام + المعالج | `System.Diagnostics.Process` | - |
| **تجميع العمليات الفرعية** (مثل عمليات Brave المتعددة) تحت صف واحد قابل للتوسيع | تجميع يدوي بالـ ViewModel + مجموع حي | يحل مشكلة اختلاف الأرقام عن تاسك مانجر |
| **تفريغ الذاكرة (Trim)** لعملية أو لمجموعة كاملة | `EmptyWorkingSet` | آمن 100%، قابل للتراجع تلقائيًا |
| **حد صارم للذاكرة (Hard Limit)** | Windows **Job Objects** | ⚠️ خطر - راجع التحذير تحت |
| **تصغير لصينية النظام (System Tray)** بدل الإغلاق | `NotifyIcon` (WinForms) داخل WPF | البرنامج يضل شغال بالخلفية، الخروج الفعلي من قائمة الصينية فقط |
| **تنبيه صوتي + بالون** لما عملية تتجاوز حد رام محدد | `SystemSounds` + `NotifyIcon.ShowBalloonTip` | قابل للتعطيل من صندوق الاختيار بالواجهة |
| علامة "عملية مشبوهة ⚠" | مقارنة 3 طرق تعداد عمليات مختلفة | كاشف تناقضات بسيط، مو أداة أمنية كاملة |

## الميزات الجديدة - تفاصيل الاستخدام

**تجميع العمليات (حل مشكلة الأرقام):** كل العمليات اللي عندها نفس
الاسم (متل عمليات Brave الفرعية) تنعرض تحت صف واحد بالاسم، ومجموع
الرام/المعالج بيكون **مجموع فعلي لكل الأطفال** — هذا هو نفس منطق
تاسك مانجر بتبويب "Processes"، فلازم يتطابق الرقم الآن. اضغط السهم
▶/▼ يسار اسم المجموعة لتفتح/تسكر تفاصيل كل PID لحاله.

**صينية النظام:** زر الإغلاق (X) ما بيقفل البرنامج — بيصغّره لصينية
النظام وبيضل يراقب بالخلفية. للخروج الفعلي: كليك يمين على أيقونة
الصينية → "خروج نهائي". دبل-كليك على الأيقونة يرجّع النافذة.

**التنبيه الصوتي:** فيه خانة "الحد (MB)" فوق الجدول — أي عملية مفردة
(مو مجموع مجموعة) توصل لهاي القيمة، بتسمع صوت تنبيه + بالون من
الصينية باسم العملية والقيمة. التنبيه ما بيتكرر لنفس العملية إلا
لما ترجع تحت الحد وتتجاوزه من جديد (عشان ما يصير إزعاج متكرر).

## تحذيرات مهمة (اقرأها قبل ما تعتمد على التطبيق)

1. **الحد الصارم مو "تحكم لطيف"**: لما عملية توصل لسقف الذاكرة اللي
   حددته، أي محاولة تخصيص ذاكرة جديدة من جهتها **تفشل فورًا** من
   طرف ويندوز نفسه. أغلب البرامج ما مبرمجة تتعامل مع هذا الموقف
   بلطف — ممكن تعلّق، تكرش، أو تفقد بيانات غير محفوظة. استخدمه
   بحذر شديد وبس على برامج ثانوية مو حساسة (مو على متصفحك المفتوح
   عليه شغل مثلاً).

2. **إزالة الحد الصارم مو ممكنة 100%**: بمجرد ما تربط عملية بـ
   Job Object، ما تقدر "تفكها" منه فعليًا. الحل العملي اللي
   الأداة تستخدمه هو رفع السقف لأعلى قيمة ممكنة، وهذا كافٍ عمليًا
   لكنه مو "فك ربط" حقيقي.

3. **بعض البرامج أصلًا داخل Job Object من قبل** (مثل Google Chrome
   اللي يحط عملياته الفرعية بـ Job خاص فيه). محاولة ربطها بـ Job
   ثاني ممكن تفشل — التطبيق بيوضحلك السبب بشريط الحالة.

4. **"العمليات المخفية عن Task Manager" — بصراحة تامة**: Task
   Manager يعرض كل شي تقريبًا لأنه يعتمد نفس واجهة النظام اللي
   .NET يستخدمها. إخفاء عملية حقيقي يحتاج Rootkit بمستوى الـ
   kernel، وكشف هذا النوع يحتاج **kernel driver متخصص**، وهذا
   خارج نطاق تطبيق WPF عادي. اللي هذا التطبيق يسويه هو مقارنة
   3 طرق تعداد مختلفة (CLR، `EnumProcesses`، `CreateToolhelp32Snapshot`)
   وتعليم أي تناقض بينهم بعلامة ⚠ — هذا مؤشر يستاهل تفتّح عينك،
   مو دليل قاطع على إخفاء متعمد.

## بنية المشروع

```
RamGuard/
  App.xaml / App.xaml.cs          نقطة البداية + فحص صلاحيات Admin
  MainWindow.xaml / .cs           الواجهة الرئيسية
  Converters.cs                   محوّلات القيم للـ Binding
  Models/ProcessInfoModel.cs      نموذج صف العملية
  Services/NativeMethods.cs       كل استدعاءات Win32 API
  Services/ProcessMonitorService.cs   قراءة لائحة العمليات + CPU%
  Services/MemoryLimiterService.cs    التفريغ + Job Object limits
  Services/HiddenProcessDetector.cs   مقارنة طرق التعداد
  ViewModels/MainViewModel.cs         MVVM + Timer التحديث
  ViewModels/RelayCommand.cs          تنفيذ ICommand
  app.manifest                        طلب صلاحيات Administrator
```

## أفكار للتوسعة لاحقًا

- أيقونة بالـ System Tray + تشغيل بالخلفية
- تنبيه تلقائي (Toast) لما عملية تتجاوز نسبة رام معينة
- حفظ إعدادات الحدود لكل برنامج بملف JSON عشان تنطبق تلقائيًا
  كل ما يفتح البرنامج (تحتاج مراقبة `Process.Start` events عبر
  WMI `Win32_ProcessStartTrace`)
- Whitelist لعمليات النظام الحساسة (svchost, csrss...) عشان
  تمنع المستخدم يطبّق عليها حد بالغلط ويعلّق ويندوز
